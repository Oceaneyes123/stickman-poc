# The Money Trap production rules

- Character review candidate: `src/characters/ReferenceCharacterRig.tsx` follows the user-supplied `references/character-reference.png` (blue-hoodie Sam, white-shirt Alex), with hair removed from both at the user's request. Keep both characters hairless. Its palette/identity supersede the original tie/stripe rules within `CharacterStudy`, `BankExample` and `MovementReview`. Keep the original POC rig imports unchanged. See `src/characters/README.md`.

- Engine: Remotion + React + strict TypeScript only. Local rendering, no paid APIs or cloud jobs. Read the official Remotion skills in `.agents/remotion-official/skills/` and version-specific documentation. Match every Remotion package version.
- Preserve user changes and the references outside this project. Never commit, push, publish or overwrite another project without an explicit request.
- Output: 1920×1080, 30 fps, H.264/yuv420p MP4. Development previews use 0.5 scale. Motion depends only on frames and declared props. No timers, CSS animation, unseeded randomness, remote render-time assets or additional engines.
- Brand: navy #14243A, white #F8FAFC, yellow #F3BE58, coral #FF6B6B, teal #39B8B6. Yellow = money, coral = costs/loss, teal = alternative. Use locally bundled Inter under SIL OFL. All scene vector art is original.
- Characters: preserve Sam's side part and yellow tie; preserve Alex's glasses and teal shirt stripe. Adult proportions, consistent face, fixed segment lengths, smooth pose blends, stable feet. Held objects attach to computed hands. Test kinematics after changing rig geometry.
- Design: one clear financial reveal at a time, readable silhouettes and numbers, at least 96px side margins. No labels crossing faces, cropped hands, particle clutter, perpetual motion or subtitles by default. Most cuts are clean; camera motion is brief and restrained.
- Financial truth lives in `src/finance/math.ts`. Derive totals; never hardcode a contradictory total in a graphic. Amounts are fictional monthly take-home USD. Remaining means income minus illustrated expenses, not a complete budget or prediction. Label debt assumptions separately; do not imply the POC includes debt.
- Audio: `public/audio/poc.wav` comes from local VoiceStudio. Keep one global Audio node. Never substitute a paid service, synthesize a fake voice or declare estimated cues aligned. Do not stretch speech to reach a runtime target.
- Timing: edit narration and cue/storyboard JSON, then run `npm run timing`. Never put narration timestamps in graphics. Use compiled event frames, cue IDs and documented offsets. Both endpoints round with Math.round(ms \* 30 / 1000); duration is rounded once from measured WAV length plus declared tail. Never sum independently rounded durations.
- Regenerated narration or WAV invalidates cue hashes. Manually review phrase timestamps and refresh hashes only after alignment work. The compiler verifies structure, not listening accuracy.
- Before delivery: `npm run check`, inspect gallery and every beat/boundary, render, verify metadata and full decode. Keep technical verification separate from human creative approval and audio listening approval. State anything unverified in `out/qa-report.md`.
- Scaling: compose existing rigs, props and scene templates from data. Keep each story's text, cues and storyboard separate. No speculative platform, asset marketplace or forced-alignment dependency.
